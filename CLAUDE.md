## AI film studio

Project: **AYXA Planner Pro — Client Walkthrough Tour**
Studio root: the repository root (`c:\Users\TLZCodes\Desktop\ProPlanner`).

This deliverable is a **live screen recording**, not a promotional film. Every frame is the
running application, driven like a person would drive it. No frame is generated by a
text-to-image model, no shot is generated by a text-to-video model, and no in-frame text is
requested from a model — the only text the edit adds is a product mark and the current module
label, both drawn locally with ffmpeg `drawtext`.

### Capture

- **Driven screen recording (Chrome 412×915 @ DSR 2, Playwright `recordVideo`)** — access: CLI,
  `node scripts/studio/tour.mjs`, against the local Vite dev server at `http://127.0.0.1:8081`.
  One clip per stop, plus a *measured* warm-up offset so the edit trims the page-load head
  exactly instead of guessing. Output: `edit/tour/seg-NN.webm` and `edit/tour/manifest.json`.
- **Local graphic cards** for the opening and closing beats, rendered with the same Playwright
  browser using the app's own design tokens and fonts, so the typography matches the product.
- **No external text-to-image service is used for any asset in this deliverable.** If one is
  added later, record it here before the first generation.

### Edit

- **ffmpeg** (`ffmpeg 9.0.2-full_build`, on PATH) — access: CLI via
  `node scripts/studio/build-tour-film.mjs`, with `libx264`, `libfreetype`, `drawtext`,
  `drawbox`, `overlay`, `scale`, `fade` and the `concat` demuxer. 1080×1920 @ 30fps, CRF 17,
  `+faststart`.
- **No external text-to-video service is used for any shot.**
- Fonts for `drawtext` live in `edit/fonts/`. The path must stay **relative**: a drive-letter
  colon in `fontfile=` is parsed as the next filter option and ffmpeg rejects the whole graph.
- Frame QC is numeric, not visual: `node scripts/studio/qc-frame.mjs` decodes a frame and
  measures the overlay and label placement, because image preview is unavailable here.

### Working defaults

- One stop per module, `12–16 seconds` each, one movement per stop: hold, slow reveal, hold.
- Output folder: the studio root above; the deliverable in `master/`, and a copy in the
  conversation artifact directory.

### Audio

- **None.** The tour is deliberately silent — the client is looking at the product, and a
  narration track would only compete with their own questions. A silent AAC stream is present
  so the file plays in every player and messaging app.
- An English-only narration path exists in `scripts/studio/build-narration.mjs` and is **unused**
  by this deliverable. There is no Arabic speech voice installed on this machine
  (`Microsoft Zira Desktop` is the only suitable voice), so any narration would be English only
  and all Arabic copy would be presented visually.
